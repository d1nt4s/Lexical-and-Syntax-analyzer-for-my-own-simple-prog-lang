# Подробное объяснение изменений в IR генераторе

## Главный вопрос: зачем нужны `load` и `store`?

### Проблема старой версии

В старой версии было так:
```python
# Старая версия
int x = 10;
int y = x;
```

Генерировалось:
```
push 10
push x    # ← ПРОБЛЕМА: это просто строка "x", а не значение переменной!
```

**Проблема:** `push x` кладет на стек строку `"x"`, а не значение переменной `x`!

### Правильная модель стек-машины

В стек-машине есть **два разных понятия**:

1. **Память (переменные)** - где хранятся значения переменных
2. **Стек** - временное хранилище для вычислений

```
Память:          Стек:
x = 10          []
y = 20          []
```

Когда мы делаем `x + y`, нужно:
1. Взять значение `x` из памяти → положить на стек
2. Взять значение `y` из памяти → положить на стек
3. Выполнить операцию на стеке
4. Результат остается на стеке

### Инструкции стек-машины

#### `push <value>` - кладет ЛИТЕРАЛ на стек

```python
int x = 10;
```

**IR:**
```
push 10    # кладет число 10 на стек
store x    # берет 10 со стека и сохраняет в переменную x
```

**Что происходит:**
```
Стек: [] → [10] → [] (после store)
Память: x = 10
```

#### `load <name>` - загружает ЗНАЧЕНИЕ переменной на стек

```python
int x = 10;
int y = x;  # нужно ЗНАЧЕНИЕ x, а не строка "x"
```

**IR:**
```
push 10
store x    # x = 10 в памяти
load x     # берет ЗНАЧЕНИЕ x из памяти → кладет на стек
store y    # берет значение со стека → сохраняет в y
```

**Что происходит:**
```
Память: x = 10
Стек: [] → [10] (после load x) → [] (после store y)
Память: x = 10, y = 10
```

#### `store <name>` - сохраняет значение со стека в переменную

```python
int x = 10;
```

**IR:**
```
push 10    # стек: [10]
store x    # берет 10 со стека, сохраняет в x, стек: []
```

## Сравнение старой и новой версии

### Старая версия (неправильная)

```minilang
int x = 10;
int y = x;
```

**Старый IR:**
```
push 10
push x     # ← это строка "x", а не значение!
push y     # ← это строка "y", а не значение!
add        # ← пытается сложить строки "x" + "y" - НЕПРАВИЛЬНО!
```

**Проблема:** Стек-машина не знает, что делать со строками `"x"` и `"y"`. Это не значения переменных!

### Новая версия (правильная)

```minilang
int x = 10;
int y = x;
```

**Новый IR:**
```
push 10    # кладем литерал 10 на стек
store x    # сохраняем 10 в переменную x
load x     # загружаем ЗНАЧЕНИЕ x (10) на стек
store y    # сохраняем 10 в переменную y
```

**Правильно:** Теперь стек-машина работает с реальными значениями!

## Пример: вычисление выражения

### Исходный код
```minilang
int x = 10;
int y = 20;
int z = x + y;
```

### Старая версия (неправильная)
```
push 10
push 20
push x      # строка "x"
push y      # строка "y"
add         # что это? "x" + "y"?
push z     # строка "z"
```

### Новая версия (правильная)
```
push 10
store x    # x = 10 в памяти
push 20
store y    # y = 20 в памяти
load x     # берем ЗНАЧЕНИЕ x (10) → стек: [10]
load y     # берем ЗНАЧЕНИЕ y (20) → стек: [10, 20]
add        # складываем: [30]
store z    # сохраняем 30 в z → стек: []
```

**Пошагово:**
```
1. push 10     → стек: [10]
2. store x     → стек: [], память: {x: 10}
3. push 20     → стек: [20]
4. store y     → стек: [], память: {x: 10, y: 20}
5. load x      → стек: [10], память: {x: 10, y: 20}
6. load y      → стек: [10, 20], память: {x: 10, y: 20}
7. add         → стек: [30], память: {x: 10, y: 20}
8. store z     → стек: [], память: {x: 10, y: 20, z: 30}
```

## Зачем нужен контракт стека?

### Проблема: мусор на стеке

В старой версии:
```minilang
int x = 10;
x + 5;  // выражение как statement
```

**Старый IR:**
```
push 10
push x
push 5
add     # результат 15 на стеке - НО НИКТО ЕГО НЕ ИСПОЛЬЗУЕТ!
```

**Проблема:** На стеке остался мусор (15), который никто не использует!

### Решение: `pop` для очистки

**Новый IR:**
```
push 10
store x
load x
push 5
add     # результат 15 на стеке
pop     # удаляем мусор со стека
```

**Правило:** 
- `gen_expr()` всегда оставляет 1 значение на стеке
- `gen_stmt()` не оставляет мусора (использует `pop` если нужно)

## Зачем нужны `load_index` и `store_index`?

### Проблема: доступ к массивам

```minilang
int[] arr;
int x = arr[5];  // нужно получить элемент массива
arr[10] = 20;    // нужно сохранить в элемент массива
```

**Без специальных инструкций:**
```
push arr    # это просто имя, не массив!
push 5
???         # как получить arr[5]?
```

**С `load_index`:**
```
load arr    # загружаем массив (или указатель на него)
push 5      # индекс
load_index  # берет [массив, индекс] → кладет [значение]
```

**С `store_index`:**
```
push 20     # значение
load arr    # массив
push 10     # индекс
store_index # берет [значение, массив, индекс] → сохраняет
```

## Зачем нужны `load_field` и `store_field`?

### Проблема: доступ к полям структур

```minilang
struct Point { int x; int y; }
struct Point p;
int x = p.x;  // нужно получить поле структуры
p.y = 20;     // нужно сохранить в поле структуры
```

**Без специальных инструкций:**
```
push p      # это просто имя, не структура!
???         # как получить p.x?
```

**С `load_field`:**
```
load p      # загружаем структуру
load_field x # берет [структура] → кладет [значение поля x]
```

**С `store_field`:**
```
push 20     # значение
load p      # структура
store_field y # берет [значение, структура] → сохраняет в поле y
```

## Зачем нужны `call`, `ret`, `retv`?

### Проблема: вызов функций

```minilang
func int add(int a, int b) {
    return a + b;
}
int result = add(5, 3);
```

**Без `call`:**
```
???         # как вызвать функцию?
???         # как передать аргументы?
???         # как получить результат?
```

**С `call`:**
```
push 5      # первый аргумент
push 3      # второй аргумент
call func_add # вызывает функцию, результат на стеке
store result
```

**Внутри функции:**
```
label func_add
load a      # загружаем параметр a
load b      # загружаем параметр b
add         # складываем
retv        # возвращаем результат
```

## Итоговая таблица инструкций

| Инструкция | Что делает | Пример использования |
|------------|------------|---------------------|
| `push 10` | Кладет литерал на стек | `int x = 10;` |
| `load x` | Загружает ЗНАЧЕНИЕ переменной на стек | `int y = x;` |
| `store x` | Сохраняет значение со стека в переменную | `int x = 10;` |
| `load_index` | Загружает элемент массива | `int x = arr[5];` |
| `store_index` | Сохраняет в элемент массива | `arr[5] = 10;` |
| `load_field x` | Загружает поле структуры | `int x = p.x;` |
| `store_field x` | Сохраняет в поле структуры | `p.x = 10;` |
| `call func_add` | Вызывает функцию | `add(5, 3)` |
| `ret` | Возврат из процедуры | `proc test() { ... }` |
| `retv` | Возврат из функции со значением | `func int test() { return 5; }` |
| `pop` | Удаляет значение со стека | `x + 5;` (выражение как statement) |

## Почему это важно?

1. **Правильная модель стек-машины**: разделение памяти и стека
2. **Чистый стек**: нет мусора после statements
3. **Поддержка сложных конструкций**: массивы, структуры, функции
4. **Готовность к интерпретации**: IR можно выполнить на реальной стек-машине

## Визуализация работы

```
Исходный код:  int x = 10; int y = x;

Память: {}              Стек: []
  ↓
push 10
Память: {}              Стек: [10]
  ↓
store x
Память: {x: 10}         Стек: []
  ↓
load x
Память: {x: 10}         Стек: [10]
  ↓
store y
Память: {x: 10, y: 10}  Стек: []
```

## Вывод

**Старая версия** была упрощенной и неправильной:
- `push x` клал строку, а не значение
- Не было разделения памяти и стека
- Нельзя было работать с массивами и структурами

**Новая версия** правильная:
- `load x` загружает реальное значение переменной
- `store x` сохраняет значение в переменную
- Есть поддержка массивов, структур, функций
- Чистый стек после каждого statement

Это стандартная модель стек-машины, используемая в реальных компиляторах!
