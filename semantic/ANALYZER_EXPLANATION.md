# Объяснение работы SemanticAnalyzer

## Общая идея

Семантический анализатор проходит по AST (дереву разбора) и проверяет **правильность программы**:
- Все ли переменные объявлены перед использованием?
- Нет ли дублирования имен?
- Существуют ли поля в структурах?
- Объявлены ли вызываемые функции?

## Основные компоненты

### 1. Области видимости (Scopes)

**Что это?** Область видимости - это "контекст", в котором видны переменные.

```python
self.global_scope = Scope()  # Глобальная область (для функций, глобальных переменных)
self.current_scope = Scope()  # Текущая область (может быть вложенной)
```

**Пример:**
```minilang
int x = 10;        // ← в глобальной области
{
    int y = 20;    // ← в локальной области (внутри блока)
    x = 5;         // ← x видна (она в глобальной области)
}
y = 30;           // ← ОШИБКА: y не видна вне блока
```

### 2. Таблица символов (Symbol Table)

**Что это?** Словарь, который хранит информацию о всех объявленных именах.

```python
# Когда встречаем: int x = 10;
symbol = Symbol(name="x", kind="var", data=decl_node)
scope.define(symbol)  # Добавляем в таблицу

# Когда встречаем: x = 5;
symbol = scope.lookup("x")  # Ищем в таблице
if symbol is None:
    raise SemanticError("Undeclared variable 'x'")
```

## Алгоритм работы (метод `analyze`)

### Шаг 1: Сбор объявлений (первый проход)

```python
# Проходим по всем statements и собираем объявления
for stmt in program.stmts:
    if isinstance(stmt, StructDecl):
        self._check_struct_decl(stmt)  # Проверяем дублирование полей
    elif isinstance(stmt, EnumDecl):
        self._check_enum_decl(stmt)    # Проверяем дублирование членов
    elif isinstance(stmt, FuncDef):
        self._declare_func(stmt)       # Добавляем функцию в таблицу символов
```

**Зачем два прохода?**
- В первом проходе собираем все объявления (struct, enum, функции)
- Во втором проходе проверяем использование (переменные, функции, поля)

**Пример:**
```minilang
func int add(int a, int b) { ... }  // ← первый проход: объявляем функцию
int result = add(5, 3);              // ← второй проход: проверяем, что add существует
```

### Шаг 2: Проверка использования (второй проход)

```python
# Теперь проверяем все statements
for stmt in program.stmts:
    self._check_stmt(stmt)  # Проверяем каждое statement
```

## Как проверяются разные конструкции

### 1. Объявление переменной (`_check_decl`)

```minilang
int x = 10;
```

**Что происходит:**
1. Проверяем, не объявлена ли уже переменная `x` в текущей области
2. Если нет - добавляем в таблицу символов
3. Проверяем инициализатор (если есть): `_check_expr(decl.init)`

**Пример ошибки:**
```minilang
int x = 10;
int x = 20;  // ← ОШИБКА: 'x' уже объявлена
```

### 2. Использование переменной (`_check_ident`)

```minilang
int x = 10;
int y = x;  // ← используем x
```

**Что происходит:**
1. Ищем переменную `x` в текущей области видимости
2. Если не найдена - ищем в родительской области (scope.lookup ищет по цепочке)
3. Если не найдена нигде - ошибка

**Пример ошибки:**
```minilang
int y = x;  // ← ОШИБКА: 'x' не объявлена
```

### 3. Доступ к полю структуры (`_check_field_access`)

```minilang
struct Point { int x; int y; }
struct Point p;
p.x = 10;  // ← доступ к полю
```

**Что происходит:**
1. Проверяем базовое выражение `p` (это переменная)
2. Находим тип переменной `p` (это `struct Point`)
3. Ищем в `self.struct_fields["Point"]` - есть ли поле `x`
4. Если нет - ошибка

**Пример ошибки:**
```minilang
struct Point { int x; int y; }
struct Point p;
p.z = 10;  // ← ОШИБКА: поле 'z' не существует
```

### 4. Вызов функции (`_check_call`)

```minilang
func int add(int a, int b) { return a + b; }
int result = add(5, 3);  // ← вызов функции
```

**Что происходит:**
1. Ищем функцию `add` в глобальной области видимости
2. Проверяем, что это действительно функция (kind == "func")
3. Проверяем аргументы: `_check_expr(arg)` для каждого аргумента

**Пример ошибки:**
```minilang
int result = unknownFunc();  // ← ОШИБКА: функция не объявлена
```

### 5. Блоки и области видимости (`_check_block`)

```minilang
int x = 10;
{
    int y = 20;  // ← новая область видимости
    x = 5;       // ← x видна (из родительской области)
}
y = 30;  // ← ОШИБКА: y не видна
```

**Что происходит:**
1. Сохраняем текущую область видимости
2. Создаем новую область с родителем = текущая область
3. Проверяем все statements в блоке
4. Восстанавливаем предыдущую область

**Код:**
```python
old_scope = self.current_scope
self.current_scope = Scope(parent=old_scope)  # Новая область
try:
    for stmt in block.stmts:
        self._check_stmt(stmt)
finally:
    self.current_scope = old_scope  # Восстанавливаем
```

### 6. Функции (`_check_func_body`)

```minilang
func int add(int a, int b) {
    return a + b;  // ← a и b видны здесь
}
```

**Что происходит:**
1. Создаем новую область видимости (родитель = глобальная область)
2. Объявляем параметры функции в этой области
3. Проверяем тело функции

**Важно:** Параметры функции видны только внутри функции!

## Рекурсивная проверка выражений

Метод `_check_expr` рекурсивно проходит по дереву выражений:

```minilang
int x = a + b * c;  // ← сложное выражение
```

**Что происходит:**
```
_check_expr(BinOp(+, Ident(a), BinOp(*, Ident(b), Ident(c))))
  ├─ _check_expr(Ident(a))  → _check_ident(a)
  └─ _check_expr(BinOp(*, Ident(b), Ident(c)))
      ├─ _check_expr(Ident(b))  → _check_ident(b)
      └─ _check_expr(Ident(c))  → _check_ident(c)
```

## Пример полного анализа

**Код:**
```minilang
struct Point {
    int x;
    int y;
}

int a = 10;
int b = a + 5;

struct Point p;
p.x = 20;
p.z = 30;  // ← ОШИБКА
```

**Что происходит:**

1. **Первый проход** (сбор объявлений):
   - `struct Point` → проверяем поля, сохраняем в `self.struct_fields["Point"] = {"x", "y"}`

2. **Второй проход** (проверка использования):
   - `int a = 10;` → объявляем переменную `a` в глобальной области
   - `int b = a + 5;` → 
     - Объявляем переменную `b`
     - Проверяем выражение `a + 5`:
       - `a` → ищем в области, находим ✓
       - `5` → литерал, проверка не нужна
   - `struct Point p;` → объявляем переменную `p` типа `struct Point`
   - `p.x = 20;` →
     - Проверяем `p.x`:
       - `p` → находим переменную `p` типа `struct Point` ✓
       - `x` → проверяем, есть ли поле `x` в `struct Point` → есть ✓
   - `p.z = 30;` →
     - Проверяем `p.z`:
       - `p` → находим переменную `p` ✓
       - `z` → проверяем, есть ли поле `z` в `struct Point` → НЕТ ✗
       - **ОШИБКА:** `Semantic error: 8:1: Field 'z' does not exist in struct 'Point'`

## Важные моменты

### 1. Порядок проверки важен!

Сначала собираем объявления, потом проверяем использование:
```python
# Правильно:
analyze() {
    1. Собираем все объявления
    2. Проверяем использование
}

# Неправильно было бы:
analyze() {
    for stmt in stmts:
        check_stmt(stmt)  # ← может не найти функцию, которая объявлена позже
}
```

### 2. Области видимости вложены

```python
# Глобальная область
int x = 10;

# Локальная область (внутри блока)
{
    int y = 20;
    x = 5;  // ← x видна (ищем в родительской области)
}

y = 30;  // ← y не видна (она в дочерней области)
```

### 3. Функции всегда в глобальной области

```minilang
func int test() {
    int x = 10;  // ← локальная переменная функции
    return x;
}

int y = test();  // ← функция видна из глобальной области
```

## Итоговая схема работы

```
Program
  │
  ├─ Первый проход: Сбор объявлений
  │   ├─ StructDecl → проверка полей, сохранение в struct_fields
  │   ├─ EnumDecl → проверка членов
  │   └─ FuncDef → добавление в global_scope
  │
  └─ Второй проход: Проверка использования
      ├─ Decl → объявление переменной в current_scope
      ├─ Assign → проверка lvalue и expr
      ├─ Ident → поиск в current_scope
      ├─ FieldAccessExpr → проверка поля в struct_fields
      ├─ CallExpr → поиск функции в global_scope
      └─ Block → создание новой области видимости
```

## Как найти ошибку в коде

Если что-то не работает, проверь:

1. **Область видимости правильная?** (current_scope vs global_scope)
2. **Символ добавлен в таблицу?** (scope.define вызван?)
3. **Правильный scope для поиска?** (переменные в current_scope, функции в global_scope)
4. **Структура сохранена?** (struct_fields содержит нужную структуру?)
